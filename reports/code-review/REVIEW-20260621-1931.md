### 3. B-RACE-DB — Partial unique index for payment idempotency

`packages/db/migrations/20260621000000-payment-pending-unique-index.ts` — New migration:
```sql
CREATE UNIQUE INDEX IF NOT EXISTS "payments_pending_per_app"
ON "Payment" ("applicationId")
WHERE status = 'PENDING'
```
Closes the concurrent-creation race that the application-level `SELECT FOR UPDATE` check cannot cover (two concurrent calls on an empty-row set both pass the lock check before either commits, since `FOR UPDATE` requires an existing row to lock). Partial predicate means historical CONFIRMED / FAILED / REFUNDED rows are unaffected — an application may legitimately have multiple payment attempts.

`down` migration: `DROP INDEX IF EXISTS "payments_pending_per_app"`.
