## Top Recommendations for Next Run

1. **Wire B4 frontend** — Connect `BankTransferForm.handleSubmit` to the 4-step flow: (a) `POST /payments/initiate` → paymentId, (b) `POST /payments/:id/presign-proof` → `{ documentId, uploadUrl }`, (c) PUT file to `uploadUrl` via `fetch`, (d) `POST /payments/:id/submit-proof`. For auth, the API's `requireAuth` middleware accepts the `next-auth.session-token` cookie; use `credentials: 'include'` in client `fetch` calls with `NEXT_PUBLIC_API_URL` pointing to the Express API. Add idempotency: check if an existing PENDING payment exists (server component or on form load) and reuse that paymentId rather than creating a duplicate.
2. **Delete A1 manually** — Remove `/dashboard/payment/mtn/` and `/dashboard/payment/airtel/` (out of scope per CLAUDE.md). Run from kip-portal root: `Remove-Item -Recurse -Force "apps/web/src/app/(investor)/dashboard/payment/mtn"` and `...airtel`.
3. **Fix H7** — Compute the TC deadline as `windowCloseAt + 21 days` in `getTcQueueView()` and include it in the returned `TcQueueView` type rather than hardcoding `"21 Jul 2026"` in the page.
4. **Verify G3** — Confirm the `apps/web/src/app/(admin)/console/tc/layout.tsx` calls `requireRole(TC_ROLES)` (or equivalent). If absent, add the server-side RBAC guard to prevent non-TC users from accessing the queue if the middleware matcher ever misconfigures.
5. **Add `NEXT_PUBLIC_API_URL` env var** — Expose the Express API URL to the browser so client components can call it. Add to `apps/web/.env.local` docs and CLAUDE.md "Planned env vars" section.
