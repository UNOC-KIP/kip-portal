## Changes applied this run

### 1. B5 — `initiatePayment` is now idempotent (PENDING payment dedup guard)

- `apps/api/src/modules/payments/payments.service.ts` — Before creating a new `Payment` row, `initiatePayment` now calls `Payment.findOne({ where: { applicationId, status: PENDING } })`. If an existing PENDING payment is found for that application, it is returned immediately without creating a duplicate row.
- This covers the case where an investor refreshes the bank-transfer page between step 1 (initiate) and step 4 (submit-proof): the second `POST /payments/initiate` call returns the original `paymentId`, so steps 2–4 proceed against the same payment row.
- No change to the response shape (`{ payment }`) — the front-end is already compatible.

### 2. A6 — Post-submission confirmation page

- `apps/web/src/app/(investor)/dashboard/payment/pending/page.tsx` — New server component page. Shows a "Proof submitted — awaiting confirmation" message, explains the 2-business-day review SLA, lists the three steps to full submission, and provides a "Return to Dashboard" button.
- `apps/web/src/app/(investor)/dashboard/payment/bank/bank-transfer-form.tsx` — On success, now redirects to `/dashboard/payment/pending` instead of `/dashboard`. Avoids the confusing state where the investor sees `DRAFT_PAYMENT_PENDING` on the dashboard immediately after submitting proof.
