## Changes applied this run

### 1. B-RACE — `initiatePayment` idempotency check moved inside transaction

- `apps/api/src/modules/payments/payments.service.ts` — The `Payment.findOne` existence check is now inside `sequelize.transaction()` with `lock: true` (generates `SELECT … FOR UPDATE`). This serialises concurrent requests on the found rows, preventing the most common form of the race where two calls both pass the pre-transaction check simultaneously.
- **Note:** The definitive fix is a DB-level unique partial index `ON payments(application_id) WHERE status = 'PENDING'` — tracked as a future migration task. The current fix eliminates the obvious non-concurrent race and adds intent documentation.

### 2. S-LIMIT — Added LIMIT guards to unbounded admin queries

- `apps/web/src/lib/admin/queries.ts`:
  - `listWindows()` — `limit: 1000` added
  - `listPendingBankTransfers()` — `limit: 200` added
  - `getTcQueue()` — `limit: 500` added; also narrowed the included ApplicationSection rows to only `LAND_BUSINESS_PROFILE` (the only section actually read by `landSizeSqm()`), cutting unnecessary payload per row

### 3. H-ENUM — Replaced hardcoded status/action strings with enum values

- `apps/web/src/lib/admin/mappers.ts` — Added `@kip/shared` import. `SUBMITTED_STATUSES` now uses `ApplicationStatus.*` constants; `tcStatusLabel` switch cases use `ApplicationStatus.*`; `paymentLabel` uses `PaymentStatus.CONFIRMED`; `toWindowRow` switch uses `ApplicationWindowStatus.*`. If any enum value is renamed, the compiler now catches all affected references.
- `apps/web/src/lib/admin/queries.ts` — `ACTIVITY_TEXT` typed as `Partial<Record<ReviewActionType, string>>` with computed enum keys; `payment.method` comparison uses `PaymentMethod.STANBIC_TRANSFER`. Lookups cast `ra.type as ReviewActionType` (DB values are guaranteed valid by the schema).
- `apps/web/src/lib/investor-data.ts` — `ACTION_TEXT` typed as `Partial<Record<ReviewActionType, string>>`; `ACTOR_TEXT` typed as `Partial<Record<UserRole, string>>`; both use computed enum keys. Lookups cast `action.type as ReviewActionType` and `action.actor.role as UserRole`.

### 4. G-CONFIRM — Added `POST /payments/:id/confirm` endpoint (ADMIN only)

- `apps/api/src/modules/payments/payments.service.ts` — `confirmPayment()` service: validates ADMIN role, checks payment is `PROOF_UPLOADED`, then in one transaction sets `payment.status = CONFIRMED`, `payment.confirmedAt = now()`, and advances the application from `DRAFT_PAYMENT_PENDING → DRAFT`. n8n `payment-confirmed` webhook stub noted in comment for Phase 3.
- `apps/api/src/modules/payments/route.ts` — `POST /payments/:id/confirm` wired to `confirmPayment`, guarded by `requireRole(UserRole.ADMIN)`.

### 5. G-QUERY — Added `GET /payments?applicationId=` endpoint

- `apps/api/src/modules/payments/payments.schema.ts` — New file; exports `getPaymentsQuerySchema` (uuid-validated `applicationId` query param).
- `apps/api/src/modules/payments/payments.service.ts` — `getPaymentsByApplicationId()`: enforces ownership (investor sees only own; ADMIN sees any), returns payments in reverse-chronological order, capped at 20.
- `apps/api/src/modules/payments/route.ts` — `GET /payments` wired to `getPaymentsByApplicationId`.
