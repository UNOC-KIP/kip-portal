2. **Fix B5 (payment dedup)** — In `initiatePayment`, before creating a new Payment row, check if an existing `PENDING` payment already exists for this `applicationId` and return it instead of creating a duplicate. 4. **Wire TC queue unlock to window close API** — The `locked` condition currently uses a dev bypass (unlocks if any submitted app exists). Phase 3 should wire this to a proper `ApplicationWindow.status = CLOSED` transition via an admin API action + n8n webhook.
5. **Add `GET /payments?applicationId=` endpoint** — For idempotency (B5), the client needs to check for an existing payment before initiating. A simple GET endpoint guarded by ownership returns the payment or `null`.
