## Bugs

| # | File:Line | Description | Severity |
|---|---|---|---|
| B1 | `apps/api/src/modules/payments/route.ts:31-47` | Payment initiation guard allows `DRAFT` status and then resets it back to `DRAFT_PAYMENT_PENDING`. `DRAFT` means payment is already confirmed — this is an invalid status regression and the transition `DRAFT → DRAFT_PAYMENT_PENDING` is not in `validTransitions`. Should restrict to `DRAFT_PAYMENT_PENDING` only. | **high** |
| B2 | `apps/api/src/modules/payments/route.ts:37-47` | `Payment.create()` and `app.update()` are two separate writes with no transaction. If the status update fails after the payment row is created, you have a dangling `PENDING` payment with no corresponding status change. | **high** |
| B3 | `apps/api/src/modules/payments/route.ts:22,37` | `initiatePaymentSchema` accepts `amount` from the client body. The fee amount is a server-side business rule (USD 1,000 per CLAUDE.md) and should be read from env config, not trusted from the request. The client could submit any amount. | **high** |
| B4 | `apps/web/src/app/(investor)/dashboard/payment/bank/page.tsx:27-30` | `handleSubmit` simulates a network call with `setTimeout` and redirects to dashboard without calling any real API. The bank transfer form does nothing. | **med** (known stub) |

**Recommendation for B1+B2+B3:** Extract payments business logic to `apps/api/src/modules/payments/payments.service.ts`. The service should: (a) only accept `DRAFT_PAYMENT_PENDING` status, (b) read the fee amount from `env.EOI_APPLICATION_FEE_USD` (add to `env.ts`), (c) wrap `Payment.create` + any status update in `sequelize.transaction()`.
